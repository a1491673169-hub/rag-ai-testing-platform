2. RAG 检索测试 
 
不要只测试最终答案。 
 
要把整个 RAG 拆开。 
 
例如针对 Retriever 测：

那么就可以分析：

这句话面试非常重要。 
 
因为 AI 测试真正有价值的地方就是： 
 
把失败归因。 
 
不是简单地： 
 
“模型答错了。” 
 
四、生成质量怎么测试 
 
可以使用 RAGAS + 自己定义的规则。 
 
重点评价： 
 
Faithfulness 
 
回答是否受到知识库支持。 
 
Answer Relevancy 
 
有没有真正回答用户的问题。 
 
Answer Correctness 
 
和 Ground Truth 是否一致。 
 
拒答正确率 
 
知识库没有的信息，模型应该说不知道，而不是编答案。 
 
其中 Faithfulness 很适合你重点讲，因为这对应一个现在非常典型的 AI 问题： 
 
幻觉 
 
例如知识库中写： 
 
电池质保 8 年。 
 
模型却回答： 
 
电池终身质保。 
 
传统接口可能： 
 
HTTP 200 
code = 0 
 
全部通过。 
 
但是实际上： 
 
业务答案错了。 
 
这就是为什么传统接口自动化测试不足以测试 AI 应用。 
 
你可以把这个作为项目动机讲出来。 
 
五、加一个非常有价值的「版本回归测试」

十、错误归因 
====== 
 
实现一个简单： 
 
class FailureType(Enum): 
``` 
RETRIEVAL_FAILURE 
GENERATION_FAILURE 
SYSTEM_ERROR 
PASS 
``` 
 
规则： 
 
如果 reference\_document\_ids 没有出现在 Top-K： 
RETRIEVAL\_FAILURE 
 
如果正确文档已经进入 Top-K， 
但是 answer 不包含 expected\_keywords： 
GENERATION\_FAILURE 
 
如果接口异常： 
SYSTEM\_ERROR 
 
否则： 
PASS 
 
实现函数： 
 
classify\_failure(...) 
 
并为它写Pytest测试。

## Test Plan

执行并修复：

```powershell
pip install -r requirements.txt
pytest -v
python scripts/run_evaluation.py
```

验收标准：

- 所有 Pytest 测试通过。
- Evaluation 脚本能够真实执行并生成报告文件。
- 报告中的指标由测试数据和实际代码计算，不硬编码。

```powershell
uvicorn app.main:app --reload
```

## Assumptions 
 
- 新文件直接创建在当前 `项目` 文件夹根目录。 
- 现有 `1.txt` 仅作为背景材料，不修改、不删除。 
- Evaluation 脚本直接调用应用服务层，避免要求用户先启动独立服务器，同时 API 测试仍使用 FastAPI 测试客户端验证接口行为。
