# RAG 智能客服自动化测试与质量评测系统：面试讲解

## 30 秒项目介绍

我做的是一个 RAG 智能客服自动化测试项目。系统用 FastAPI 提供问答接口，Retriever 使用 TF-IDF 检索知识库，Generator 使用确定性的 MockGenerator 生成回答。项目重点不是调用大模型，而是把 RAG 拆成检索和生成两个阶段，使用 Pytest、Hit@K、Recall@K、MRR、关键词覆盖率和规则版 Faithfulness 评测质量，并自动把失败归因为检索失败、生成失败、幻觉或拒答失败。

## 2 分钟项目介绍

传统接口测试看到 HTTP 200 只能说明接口调用成功，不能说明检索和回答正确。因此我设计 `RAGService` 作为业务编排层，把 `TfidfRetriever` 和 `MockGenerator` 解耦。测试数据放在 JSONL 中，每条用例包含问题、参考文档、期望关键词、难度和场景类型。Pytest 通过参数化自动展开测试用例；Evaluation 计算检索指标、回答质量并进行错误归因。项目还提供质量门禁和 baseline/candidate 回归脚本，使 AI 版本变化可以被自动发现。

## 核心知识

- **RAG**：先检索知识，再把知识交给生成器回答。
- **Retriever**：找相关资料；**Generator**：依据资料组织答案。
- **TF-IDF**：用词的重要程度表示文本；cosine similarity 比较问题和文档向量相似度。
- **Top-K**：取相似度最高的 K 个文档。
- **Hit@K**：有没有命中正确文档。
- **Recall@K**：正确文档集合命中了多少。
- **Precision@K**：返回结果中有多少是相关的。
- **MRR**：第一个正确结果排名的倒数。
- **Faithfulness**：回答是否能被 Context 支持；当前实现是规则基线。
- **Hallucination**：回答出现 Context 无法支持的事实。
- **Prompt Injection**：用户试图改变系统规则或越权获取信息。
- **Regression Testing**：用同一测试集比较 baseline 和 candidate。
- **Quality Gate**：版本上线前必须满足的指标阈值。

## 高频面试问题

1. **为什么不用传统接口测试？** HTTP 断言只能验证协议层，不能证明回答质量，所以需要 AI 质量 Oracle。
2. **为什么拆 Retriever 和 Generator？** 为了区分找错资料和基于正确资料答错。
3. **Hit@K 和 Recall@K 区别？** Hit 只判断是否命中，Recall 还关心多个参考文档命中了多少。
4. **MRR 为什么有用？** 它能区分正确文档排第一还是排得很后。
5. **Precision@K 解决什么问题？** 判断 Top-K 中噪声是否过多。
6. **AI 测试 Oracle 怎么设计？** 组合参考文档、关键词、拒答词和上下文支持关系。
7. **模型有随机性怎么测？** MVP 使用 MockGenerator；真实模型阶段固定温度、使用阈值和多次采样。
8. **如何判断幻觉？** 检查回答事实是否能在 retrieved contexts 中得到支持。
9. **MockGenerator 有什么价值？** 无密钥、无成本、确定性，先验证测试体系本身。
10. **Retriever 找对但答案错怎么办？** 归因为 GENERATION_FAILURE，检查上下文和生成逻辑。
11. **如何做版本回归？** 同一 JSONL 用例跑 baseline/candidate，比较指标和逐条状态。
12. **为什么需要质量门禁？** 防止版本上线后效果退化，把质量要求变成可执行规则。
13. **和普通 API 自动化区别？** 增加检索质量、回答质量、幻觉和错误归因。
14. **为什么使用 TF-IDF？** 依赖少、稳定、容易解释，适合作为 MVP 基线。
15. **换 Embedding 后要改测试吗？** 主要替换 Retriever，数据、指标和归因接口可复用。
16. **测试数据怎么设计？** 覆盖正常、口语、错别字、多文档、知识缺失和干扰问题。
17. **多知识问题如何算 Recall？** 参考文档集合是分母，Top-K 命中数是分子。
18. **如何避免结果不稳定？** 固定数据、固定配置、MockGenerator 和明确阈值。
19. **性能测试看什么？** 平均响应时间、P50/P95/P99、吞吐量和失败率。
20. **项目最大不足是什么？** TF-IDF 和规则评测语义能力有限，MockGenerator 也不代表真实模型。

## 简历项目描述

- 基于 Python、FastAPI 和 Pytest 搭建 RAG 智能客服自动化测试与质量评测系统，设计覆盖正常、口语、多文档和知识缺失场景的 JSONL 测试集。
- 将 RAG 链路拆分为 TF-IDF Retriever 与 MockGenerator，实现 Hit@K、Recall@K、Precision@K、MRR 及分组评测。
- 基于关键词、参考上下文和拒答规则实现 Answer Correctness、Rule-based Faithfulness 及检索失败、生成失败、幻觉和拒答失败归因。
- 实现质量门禁与 baseline/candidate 回归脚本，自动输出质量报告和具体回归用例，保留真实 LLM、Allure 和 Locust 扩展入口。
